## Qué quiere Edu (la visión)
Una app de terminal propia: se escribe `moragent`, se entra a MORAGENT (no a Claude ni a Codex), se hace login con
lo que uno tenga (suscripciones o API keys), se conversa con un orquestador ejecutivo que despliega subagentes
**por dentro**, con memoria en capas y Obsidian. Debe sentirse como Claude Code / Codex CLI: terminal real, rápida,
obvia de usar, donde se ve el procesamiento.

Pruebas de motor y de workspace síncrono/asíncrono cubren fallo, éxito y rutas no protegidas. Las 396 pruebas, build, paquete y diff pasan; no hubo una nueva prueba viva de esta variante de plan.
- Otra prueba roja mostró que `file_text` aceptaba rutas que la copia privada nunca publica (`.git`, `node_modules` y `.moragent/{runs,tasks,sessions,memory}`), con riesgo de informar `verifiedChecks` sin archivo en el origen. El validador común de checks las rechaza ahora de forma conservadora incluso con variantes de mayúsculas para volúmenes sin distinción de caso. Las pruebas cubren tanto el bloque del usuario (sin descubrir proveedores ni crear proyecto) como el plan escrito por el modelo. Se documentaron las exclusiones en ES/EN.
- Una carrera de lectura también producía evidencia falsa: un worker comprobaba `RIGHT\n` en su copia, el archivo original cambiaba a `WRONG\n` mientras corría, y la tarea de sólo lectura terminaba `done` con `verifiedChecks`. Los checks de rutas modificadas también se revalidan en la copia dentro de la integración. La batería subió a 397/397 en Node 22 y 18; build, pack smoke y diff check pasan. Esta carrera se simuló con proveedores falsos, no con un modelo vivo.
- Prueba viva de OpenCode 1.18.30 en temporales: `opencode/big-pickle` y el default gratuito devolvieron HTTP 403, `openai/gpt-5.4-mini` devolvió HTTP 400 porque figura en el catálogo pero no está admitido con la cuenta ChatGPT, y `openai/gpt-5.6-sol` sí respondió en `readonly` sin crear el archivo pedido. - Prueba de primer uso en PTY real, proyecto temporal vacío: MORAGENT abrió en español, mostró `/help`, cambió a inglés con `/idioma en`, volvió a mostrar ayuda traducida y salió limpiamente. Prueba roja→verde ES/EN: el selector de modelos ahora usa `·` con leyenda de acceso no verificado y conserva `○` para motores desconectados; los selectores de proveedores siguen usando `✓` para un motor listo. - El guardado de `credentials.json` ahora usa archivo temporal privado y reemplazo atómico. Si el archivo existente está corrupto o ilegible, las operaciones de escritura lo conservan y `/login` informa el error sin mostrar la clave nueva; dos pruebas cubren mutadores y UI. Las lecturas siguen sin interrumpir el arranque.
- Prueba viva multiagente en PTY con `compatible`→Ollama `gemma4:latest`, sin CLIs en `PATH`: el primer plan paralelo tenía checks separados, pero backend escribió también `ui.txt` desde el contexto amplio de memoria. Para evitar ese desvío, el sobre de tarea presenta la memoria sólo como antecedente y deja la tarea asignada al final; `write_file`/`edit_file` de proveedores API rechazan rutas contractuales asignadas a otro worker, y la publicación aplica el mismo límite incluso a proveedores CLI. Una copia que lo viole queda sólo para inspección manual. ## Riesgos siguientes
1. Probar `compatible` con más servidores y variantes de protocolo (Ollama y LM Studio locales ya pasaron en flujos básicos), y medir el límite de contexto/planificación de modelos pequeños como `qwen3.5:4b` en tareas integrales. El fallback sin herramientas evita el HTTP 500 de protocolo, pero no garantiza un plan completo. La detección de modelos no-chat por ID es heurística.
2. Probar rendimiento de copias en proyectos grandes; la prueba viva con Claude + Codex pasó, pero un CLI con acceso irrestricto aún podría elegir una ruta absoluta externa. Los symlinks externos ahora impiden preparar el worker. Falta sandbox del SO y una resolución asistida de conflictos reales entre archivos; la aplicación segura sólo funciona tras restablecer la huella base. La detección de `node_modules` es por metadatos, no por contenido criptográfico; podría omitir cambios adversariales que preserven esos metadatos.
3. Verificar terminal e inicio de sesión en Windows/Linux reales; Gemini CLI sigue sin prueba viva. Reintentar la denegación real de herramientas de OpenCode cuando su proveedor responda y comprobar límites de permisos bajo configuraciones de agente personalizadas.
4. Repetir pruebas de experiencia con proyectos de tamaño real y usuarios nuevos antes de considerar una publicación; la PTY de copia grande y cancelación pasó en esta Mac, pero no demuestra rendimiento o cancelación igual en otras máquinas y sistemas.
