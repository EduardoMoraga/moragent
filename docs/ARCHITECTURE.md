# MORAGENT v4 — Architecture contract

> This file is the contract every crew member builds against. If you need to change an
> interface, write the change here first and tell the lead. Do not edit modules you do not own.

## 1. What MORAGENT is

One command installs an **executive orchestrator** that turns any repo into an agentic project:

- a **crew** of coding CLIs (Claude Code, Codex, Antigravity `agy`, Pi, OpenCode, Gemini) running in
  real terminal panes (Orca, herdr, tmux) or headless when no multiplexer exists;
- a **task bus** on disk so agents from different vendors hand work to each other;
- a **layered memory** (canonical / episodic / transient + procedural = skills);
- **spec-driven phases** (explore → propose → spec → design → tasks → apply → verify → archive);
- an **Obsidian second brain** per project, written automatically;
- the same **plugin** for Claude Code and Codex (shared `SKILL.md` files).

Principles: zero runtime dependencies (Node ≥ 18 stdlib only), markdown on disk is the source of
truth, every command works without a TTY, bilingual ES/EN, `--json` on every read command,
`--dry-run` on every command that writes outside `.moragent/`.

## 2. Layout of a MORAGENT project

```
<repo>/
├── AGENTS.md              canonical instructions (managed block between moragent markers)
├── CLAUDE.md              "@AGENTS.md" + managed block
├── GEMINI.md              "@AGENTS.md"-equivalent for Antigravity/Gemini
├── .claude/skills/moragent-*/SKILL.md     ← synced copies
├── .agents/skills/moragent-*/SKILL.md     ← synced copies (Codex, Pi, OpenCode)
└── .moragent/                             ← also the Obsidian folder
    ├── moragent.json      config (see §4)
    ├── Home.md            Map of Content (generated by brain)
    ├── memory/
    │   ├── canonical/     durable truth: decisions, conventions, architecture (git-tracked)
    │   ├── episodic/      what happened: sessions, task results, one file per event (git-tracked)
    │   └── transient/     scratch + handoffs, expires (git-ignored)
    ├── specs/<slug>/      proposal.md spec.md design.md tasks.md  (+ state.json)
    ├── tasks/<id>.json    task bus records;  <id>.md = the prompt envelope sent to the agent
    ├── skills/<name>/SKILL.md   project skills (procedural memory) — source for sync
    ├── context/<role>.md  compiled context packs (git-ignored)
    └── runs/              pane handles, headless logs (git-ignored)
```

## 3. Module ownership

| Area | Path | Owner |
|---|---|---|
| CLI router, args, config, paths, fs helpers, i18n, `init`, `sync`, `help` | `src/core/*`, `src/cli.js`, `src/commands/{init,sync,help,config}.js`, `templates/instructions/*` | **lead** (Claude orchestrator) |
| Multiplexers, CLI adapters, task bus, `up/down/dispatch/task/done/wait/crew/run` | `src/mux/*`, `src/crew/*`, `src/bus/*`, matching `src/commands/*` | **backend** (Codex) |
| Wizard, dashboard, board rendering, doctor, README, landing | `src/ui/*`, `src/commands/{doctor,dashboard}.js`, `README*.md`, `docs/site/*` | **frontend** (Claude) |
| Memory tiers, recall, context packs, Obsidian brain | `src/memory/*`, `src/brain/*`, `src/commands/{memory,brain,context}.js` | **helper** (Antigravity) |
| Templates, specs/SDD, plugin manifests, installers, CI | `templates/*`, `src/spec/*`, `src/commands/spec.js`, `plugin/*`, `.claude-plugin/`, `.codex-plugin/`, `install.sh`, `install.ps1`, `.github/*` | **dev** (Pi) |

Tests: `test/<area>.test.js` with `node:test` + `node:assert/strict`, owned by the area owner.
Run all with `npm test`. Tests must never launch a real agent CLI or multiplexer — stub `exec`.

## 5. Shared core API (lead) — import, don't reimplement

PRESETS, CLI_IDS, defaultConfig({ project, lang, preset })

which(bin) -> string|null

## 6. Command contract

Every file in `src/commands/` default-exports:

```js
export default {
  name: 'dispatch',
  aliases: ['d'],
  group: 'crew',                      // start | crew | memory | spec | brain | system
  summary: { es: '…', en: '…' },
  usage: 'mora dispatch <role> "<task>" [--spec <slug>] [--headless] [--json]',
  async run(argv, ctx) { /* argv = parsed args, ctx = { root, config, lang, json } */ return 0 }
}
```

`argv` from `src/core/args.js#parse`: `{ _: [positionals], flags: { name: value|true } }`.
`--flag=value`, `--flag value`, `-f`, `--no-flag` (→ false) supported. The router registers
commands from the list in `src/commands/index.js` — **add your command there** (one line).

## 7. Crew adapters (backend) — `src/crew/adapters.js`

```js
ADAPTERS: { claude, codex, agy, pi, opencode, gemini }
adapter = {
  id, label, bin,
  installed() -> bool,
  interactive({ root, role, member, autonomy }) -> string
  headless({ root, role, prompt, member, autonomy }) -> [cmd, ...args]
  instructionFiles: ['AGENTS.md'] | ['CLAUDE.md'] | ['GEMINI.md', 'AGENTS.md'],
  skillsDirs: ['.claude/skills'] | ['.agents/skills'] | ['.pi/skills'] | ['.opencode/skill'],
  docs, install,
}
autonomyFor({ autonomy, member, headless=false }) -> 'auto' | 'full' | 'ask'
getAdapter(id) -> adapter (throws UNKNOWN_CLI)
```

Autonomy modes are per member (`crew.<role>.autonomy`) or per launch (`mora up --yolo` → `full`).
Headless `ask` is coerced to `auto` so unattended agents can finish and call `mora done`/`mora block`.
Claude `auto` grants a narrow tool set for `mora`, tests, node and git inspection; Codex headless uses
workspace-write without approval prompts; `agy` uses its workspace sandbox with prompt skipping in `auto`.

## 8. Multiplexers (backend) — `src/mux/*.js`

```js
detectMux(pref = 'auto') -> 'orca' | 'herdr' | 'tmux' | 'headless'
getMux(name) -> {
  name,
  available() -> bool,
  spawn({ root, role, title, command, cwd, anchor, member, adapter, autonomy, layout }) -> { handle, layout?, session? }
  send(handle, text, { enter=true, root, role, adapter, member, taskId, autonomy, layout }),
  read(handle, { lines=60, root }) -> string,
  close(handle, { root, layout }),
  alive(handle, { root }) -> bool,
}
```

Pane handles persist in `.moragent/runs/panes.json` as
`{ role: { mux, handle, cli, autonomy, layout, startedAt } }`. Headless session state persists in
`.moragent/runs/headless.json` and logs go to `.moragent/runs/<role>-<task>.log`.

`mora up` writes a per-project shim in `.moragent/runs/bin/mora` (and `mora.cmd`) via
`src/core/shim.js#ensureShim(root)` before real pane launches. Multiplexers prepend this directory to
pane `PATH`, so an agent always calls the same MORAGENT installation. Dry runs do not create or inject
the shim.

## 9. Task bus (backend) — `src/bus/tasks.js`

Task record `.moragent/tasks/T-0001.json`:

```json
{ "id": "T-0001", "title": "…", "role": "backend", "status": "queued",
  "spec": "auth-login", "body": "…", "createdAt": "…", "updatedAt": "…",
  "result": null, "files": [], "by": "lead" }
```

Status: `queued → sent → running → done | failed | blocked`.
Dispatch writes `.moragent/tasks/T-0001.md` (the **envelope**) and sends the agent one short line:
`Lee y ejecuta .moragent/tasks/T-0001.md` (or English). `mora resend <id>` rewrites the envelope and
re-sends queued/sent tasks to the registered live pane. The envelope contains: mission, task, spec
excerpt, relevant memory (from `memory.contextPack`), acceptance criteria, and the exit protocol:
`mora done T-0001 --summary "…" [--files a,b]` or `mora block T-0001 --reason "…"`.

```js
createTask({ root, title, role, body, spec, by }) -> task
getTask(root, id)  listTasks(root, { status, role })  updateTask(root, id, patch)
nextId(root) -> 'T-0001'
```

`mora done` also calls `memory.add({ tier: 'episodic', … })` so results become memory.

## 10. Memory (helper) — `src/memory/index.js`

A memory note is markdown with frontmatter, Obsidian-compatible:

```markdown
---
id: 2026-09-27-auth-uses-jwt
tier: canonical            # canonical | episodic | transient
kind: decision             # decision | convention | fact | episode | handoff | note
title: Auth uses JWT with refresh rotation
tags: [auth, backend]
links: [T-0004, auth-login]
by: backend
created: 2026-09-27T14:03:00-03:00
---
Body… with [[wikilinks]] to specs, tasks, other notes.
```

```js
add({ root, tier, kind, title, body, tags=[], links=[], by }) -> { id, path, note }
list({ root, tier, limit }) -> note[]         // newest first
recall({ root, query, tiers, limit=8, includeSpecs=true }) -> [{ note, score, snippet }]
promote({ root, id, kind }) -> note           // episodic|transient → canonical + traceability
capture({ root, from, input }) -> note|null   // hook target; silent no-op outside a project
getNote(root, id) -> note|null
gc({ root, days, dryRun=false }) -> { count, removed }
contextPack({ root, role, query, budget=6000 }) -> string   // memory + relevant specs
```

`mora init` installs a project-local Claude `SessionEnd` hook by default in `.claude/settings.json`.
`mora sync --hooks` installs or previews the same hook; `mora sync --hooks --global` may add Codex
`notify` to the user-level `~/.codex/config.toml`. MORAGENT never creates project-local
`.codex/config.toml` because Codex ignores `notify` there.

## 11. Brain (helper) — `src/brain/obsidian.js`

```js
findVaults() -> [{ path, name }]
link({ root, vault, folder, mode: 'link'|'copy' }) -> { target }
buildHome(root) -> path               // writes .moragent/Home.md MOC with wikilinks and current state
sync(root)                             // copy mode refresh + Home rebuild
refresh(root)                          // rebuilds Home and refreshes copy-mode brain when configured
```

Commands that change memory/task/spec state may call brain refresh so Obsidian reflects current work.

## 12. Specs (dev) — `src/spec/index.js`

```js
PHASES = ['explore','propose','spec','design','tasks','apply','verify','archive']
newSpec({ root, slug, title, lang }) -> dir     // from templates/spec/*.md
specState(root, slug) -> { phase, done: [...], next, hint }
advance(root, slug) -> state
tasksFromSpec(root, slug) -> [{ title, role, doneWhen, done }]
archiveSpec(root, slug) -> state
listSpecs(root) -> [{ slug, phase, done, next, hint }]
```

State is derived from files on disk. `explore` is done once a spec exists. Placeholder task lines with
`<…>` are ignored. Verification is detected from `## Verificación` / `## Verification` without `TODO:`.

## 13. Sync (lead) — `mora sync`

Regenerates managed blocks in AGENTS.md / CLAUDE.md / GEMINI.md from `templates/instructions/`
and the config, copies `.moragent/skills/*` + bundled `templates/skills/*` into every
`skillsDirs` of every CLI used in the crew. Never touches content outside the markers.

```js
syncProject(root, cfg, { dryRun=false }) -> { files, skills, clis }
installHooks(root, clis, { dryRun=false, global=false }) -> writtenPaths[]
```

`mora sync --hooks --dry-run` previews hook changes without writing. `mora init` calls sync and installs
project-scoped hooks unless `--no-hooks` is passed.
